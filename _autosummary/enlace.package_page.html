enlace.package_page¶

Serve an app’s page from its Python package: the shell and its /ui/ assets.

Some apps ship their whole page inside their Python package: a script and a stylesheet (and maybe vendored files) under a data directory, plus a tiny HTML shell that tells the script where its API lives. Before this module, the host committed that generated shell as the app’s frontend/index.html and the app served its own assets from a hand-written /ui/{name} route. Now one app.toml key does both, and a UI change ships by upgrading the package:

page_from_package = "mypkg"     # assets in mypkg/data/ui, generic shell

[page_from_package]             # or the full table
package = "songleaf"
assets = "data/web"             # directory inside the package
shell = "songleaf.web:page_shell"   # the app's own shell, if it has one

What enlace serves for such an app (name, API at route_prefix):

  • /{name}/ and every path under it: the shell (client-side routing), with Cache-Control: no-cache and an ETag, so a package upgrade reaches the browser on its next load.

  • {route_prefix}/ui/<file>: the files of the package’s assets directory, always revalidated. Mounted ahead of the app; what it does not serve falls through to the app, so the app’s own /ui routes keep working.

The shell is the app’s own (shell = "module:function", called as function(api=..., base=..., title=...) and returning HTML) or enlace’s generic one (page_shell()): window.<GLOBAL> = {api, base, title} and the scripts and stylesheets, loaded from the assets route.

The app does not change and does not import enlace. Run alone, it keeps serving its own page however it already did.

The package is imported into the gateway, as an asgi app is. A failure to import it, find its assets directory or build the shell is a load failure of the app (see enlace.degraded): loud, and local to that app.

class enlace.package_page.PackageAssets(*args, allowed=(), cache_control='no-cache', fallback=None, route='ui', **kwargs)[source]¶

Bases: StaticFiles

A package’s page files, always revalidated, optionally allowlisted.

Hidden files (a path segment starting with .) and __pycache__ are never served. A request it does not serve (no such file, not on the allowlist, a method other than GET/HEAD, a websocket) goes to fallback when one is given (the app’s own mount, so a route the app has under the same segment keeps working), else gets a 404 / 405. fallback sees the scope the app’s mount would have given it: the assets route segment moves from root_path back into the path.

enlace.package_page.page_shell(*, api, base='', title='', global_name='APP', scripts=('app.js',), stylesheets=('style.css',), assets_route='ui')[source]¶

The generic shell: window.<global_name> = {api, base, title}, then assets.

api is where the app’s API is mounted (its files are under {api}/{assets_route}/), base where the page lives.

>>> shell = page_shell(api="/api/demo", base="/demo", title="Demo")
>>> '<script src="/api/demo/ui/app.js"></script>' in shell
True
>>> 'window.APP = {"api": "/api/demo", "base": "/demo", "title": "Demo"}' in shell
True
